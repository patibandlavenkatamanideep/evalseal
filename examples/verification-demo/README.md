# You were handed a receipt. What can you actually establish?

Someone gives you this directory and a claim: *"our eval scored 0.90."* You have no
access to their machine and no reason to take their word for anything.

This walkthrough is what you can check, what each check buys you, and — the part that
matters — **what happens when something has been tampered with.** A demo where
everything is green teaches nothing, because you cannot tell a working check from a
check that always passes. So half of this page is failures.

> **Run every command from the repository root.** A receipt records the *paths* its
> artifacts were sealed at. Run from elsewhere and `verify --artifacts` reports
> `missing` rather than `ok` — which is itself worth seeing once: a digest can only be
> matched against a file you can find.

No API key. No network. Nothing here contacts anything.

## What's in the bundle

| file | what it is |
|---|---|
| `report.json` | the sealed receipt |
| `ledger.jsonl` | the hash-linked ledger it was sealed into |
| `ledger.jsonl.sig.jsonl` | an Ed25519 signature over the ledger head |
| `signing.pub` | the public half of the signing key |
| `anchor.json` | the anchor, binding receipt + ledger head + signature + artifacts |
| `cassette.json` | the artifact the receipt binds by digest |
| `fixture-tsa/ca.pem` | the root for the RFC 3161 proof in the anchor |

> ### ⚠️ The timestamp in this bundle is a fixture, not a timestamp
>
> `fixture-tsa/` is a throwaway authority generated by this repository's own tests, and
> its "attestation" attests **nothing**. It exists so the walkthrough can show the
> signature-verification path working. A real anchor needs a real authority you chose;
> see [docs/external-anchoring.md](../../docs/external-anchoring.md).

## 1. Has the record been edited since it was sealed?

```bash
evalseal verify --ledger examples/verification-demo/ledger.jsonl
```
```
Chain intact: 1 record(s).
```

**Establishes:** every record's hash matches its content, and each links to the one
before. **Trust required: nobody.** You recompute it.

**Does not establish:** that the numbers are true, or that anyone ran anything.

## 2. Are the files it was sealed against still the same files?

```bash
evalseal verify --ledger examples/verification-demo/ledger.jsonl --artifacts
```
```
Chain intact: 1 record(s).
ok           cassette: examples/verification-demo/cassette.json matches the sealed digest
```

**Establishes:** the cassette is byte-identical to the one the verdicts came from.
**Trust required: nobody.**

**Does not establish:** that the responses in it are what a model really said. A digest
proves identity, not provenance.

## 3. Who sealed it?

```bash
evalseal verify --ledger examples/verification-demo/ledger.jsonl \
  --public-key examples/verification-demo/signing.pub
```
```
Chain intact: 1 record(s).
1 signature(s) valid; records 0-0 of 1 are signed.
```

**Establishes:** the holder of the matching private key signed a ledger whose head was
this. **Trust required:** that the key was not shared or stolen.

**Does not establish:** *when* they signed, or that they did not rebuild the ledger and
re-sign it. A signature does not constrain the key holder.

## 4. Is this the receipt the anchor covers?

```bash
evalseal anchor-verify examples/verification-demo/anchor.json \
  examples/verification-demo/report.json \
  --ledger examples/verification-demo/ledger.jsonl \
  --tsa-ca examples/verification-demo/fixture-tsa/ca.pem
```

Every layer is named separately, and the one that *cannot* be checked says so:

```
ok   anchor integrity: the anchor's content matches its subject digest
ok   receipt integrity: the receipt's content matches its sealed hash
ok   receipt identity: this is the receipt that was anchored
ok   ledger head: record 0 is still the anchored head; later appends are allowed
ok   sealed:cassette: matches the digest sealed in the receipt
ok   created_at (not verified): ... is the anchoring machine's own clock. Nothing here
     establishes that the anchor was made then; a backdated clock produces a backdated
     anchor
ok   external proof (rfc3161): signature verified against the certificate you supplied;
     revocation not checked
Anchor verified.
```

Drop `--tsa-ca` and the last line changes to *message imprint checked, TSA signature
NOT verified by EvalSeal* — because without a root, nothing about the signature is
established. The check reports itself as **not run**, never as passed.

## What this walkthrough does not cover

**Whether the numbers are worth acting on.** Integrity and precision are different
questions, and passing every check above says nothing about the second. This receipt
scored 0.90 with one of its two cases flipping once in five runs - and five runs cannot
tell you whether that case flips 4% of the time or 50%. Checking that is a separate
step, with its own command, on its own branch.

## Now break it

### Edit a score in the ledger

```bash
python3 -c "
import json; p='examples/verification-demo/ledger.jsonl'
d=json.loads(open(p).read().strip()); d['results'][0]['scores'][0]=0.0
open(p,'w').write(json.dumps(d)+'\n')"
evalseal verify --ledger examples/verification-demo/ledger.jsonl; echo "exit: $?"
```
```
TAMPER DETECTED at record 0: content hash does not match.
exit: 1
```

Not "invalid" — it names the record. Restore with `git checkout examples/verification-demo/`.

### Edit the bound artifact

```bash
echo '{"tampered": true}' > examples/verification-demo/cassette.json
evalseal verify --ledger examples/verification-demo/ledger.jsonl --artifacts; echo "exit: $?"
```
```
Chain intact: 1 record(s).
changed      cassette: examples/verification-demo/cassette.json does not match the
             digest sealed with this record
exit: 1
```

The chain is still intact — nobody touched the ledger. The *world the verdicts came
from* changed, and that is a separate check with a separate answer.

### Edit the receipt

```bash
python3 -c "
import json; p='examples/verification-demo/report.json'
d=json.load(open(p)); d['results'][0]['scores'][0]=0.0
open(p,'w').write(json.dumps(d, indent=2))"
evalseal anchor-verify examples/verification-demo/anchor.json \
  examples/verification-demo/report.json \
  --ledger examples/verification-demo/ledger.jsonl; echo "exit: $?"
```
```
FAIL receipt integrity: the receipt's content does not match its sealed hash
exit: 1
```

### Verify the timestamp against the wrong root

```bash
evalseal anchor-verify examples/verification-demo/anchor.json \
  examples/verification-demo/report.json \
  --ledger examples/verification-demo/ledger.jsonl --tsa-ca some-other-ca.pem
```
```
verification FAILED: the signing certificate was not issued by any root you supplied
```

Which is the point of supplying the root yourself. A root carried inside the anchor
would be a root its author chose.

### Delete the artifact entirely

```bash
rm examples/verification-demo/cassette.json
evalseal verify --ledger examples/verification-demo/ledger.jsonl --artifacts
```
```
missing      cassette: examples/verification-demo/cassette.json is not here; its digest
             cannot be checked
```

**Reported as missing, never as passing.** This is the limit worth remembering: a digest
can only be matched against a file somebody kept.

Restore everything with `git checkout examples/verification-demo/`.

## What you still cannot establish

Having passed every check above, these remain open — and no amount of verifying closes
them:

- **That the eval ran at all.** A receipt records bytes, not events. Someone able to
  write a cassette can seal a receipt for a run that never happened.
- **That the provider served the model it named.** `served_model` is whatever the
  response said.
- **That the inputs were honest.** A rubric that grades nonsense seals cleanly.
- **When any of it happened.** Every timestamp here is the author's own clock, except
  the RFC 3161 proof — and that one rests on an authority, not on EvalSeal.
- **That this was the only run.** See
  [docs/pre-registration.md](../../docs/pre-registration.md).
- **That a tool trace is complete.** For agent evals, EvalSeal binds what the harness
  recorded and cannot know what it omitted.

The honest summary: **these checks establish integrity, provenance and comparability.
They do not establish truth.** [THREAT_MODEL.md](../../THREAT_MODEL.md) draws every line
precisely.
